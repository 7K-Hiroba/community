# Hiroba community

Hiroba is the **pre-v1, Apache-2.0 community home for Inari extensions, catalog packages, scaffold templates, OCI Helm charts, and observability assets**. One repository per application keeps ownership and lifecycles independent while shared immutable workflows and trusted-publishing rules provide consistent standards.

Start with:

- [Governance](GOVERNANCE.md) and [maintainer teams](MAINTAINERS.md)
- [Application onboarding](docs/governance/onboarding.md)
- [Application identity registry](registry/README.md)
- [Trust tiers](docs/governance/trust-tiers.md)
- [Organization resource access](docs/governance/org-resource-access.md)
- [Commercial and open-source boundary](docs/legal/commercial-boundary.md)
- [Trademark and brand policy](TRADEMARKS.md)
- [CLA and contribution status](CLA.md)

The [Hiroba organization profile](https://github.com/7K-Hiroba) and published [Inari packaging governance](https://github.com/7K-Inari/inari-docs/blob/main/docs/extension-authors/packaging-governance.md) provide the surrounding platform context. Security reports use the [private security process](https://github.com/7K-Hiroba/.github/blob/main/SECURITY.md), never public issues.

**External contributions are currently paused** while explicit `7K-Hiroba` CLA coverage and the remaining launch gates stay under owner/counsel review. Bug reports and feature requests may still be useful; external pull requests must not be merged.

A static listing and GitHub Pages are separately gated future work, not features of this foundation change.
